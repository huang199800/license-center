# 源码公开与秘密管理

公开的是协议、SDK、业务实现与部署脚本；安全边界不依赖源码或公钥保密。客户能改源码/运行环境时仍可绕过本地强制校验。签名私钥只在运营方授权中心持久目录，不上传到GitHub，不进入客户端，不作为镜像build-arg。高价值能力应在运营者控制的服务端执行。

## 首次初始化

没有固定密码。安装生成独立随机管理员密码、签名密钥、数据加密密钥和备份口令；管理员密码只以scrypt哈希入库。TOTP初次绑定材料和密码通过受保护文件交付，终端只显示文件位置，不显示内容。备份两个口令分开保存并与加密包隔离；把它们复制到同一个同权限目录会破坏分权保管目标。

无人值守配置是0600的JSON，不执行shell表达式；仅允许已知键。秘密文件必须绝对路径、当前操作员/root所有、权限0600。环境变量/Bash xtrace、Git trace输出和URL凭据不得用于传输GitHub Token。公共源码默认不需要下载凭据；切私有时只读部署密钥或单库Contents:read细粒度Token即可，不需要账号级Token。

初始化失败后可能保留部分数据/key；安装器会停止并要求受控恢复，不会悄悄清库。重复安装已有健康同提交部署只检查和启动，不能改变密钥身份。丢失key会影响原客户端信任，密钥泄露需走信任更新，而不是只在后台点“撤销”。

## Git与发布前检查

`.gitignore`排除.env、运行配置、数据、key/pem、DB/WAL/SHM、lcb/lcb2、日志、Token文件、密码/秘密文件、MFA绑定材料及交付交换目录。`.dockerignore`另外排除运行状态和秘密路径。 `.env.example` 与 `deploy/install-config.example.json` 不含真实秘密。

发布前执行：

```sh
git add .
python3 scripts/scan_secrets.py
# 审阅 git diff --cached；扫描通过后再提交发布。
```

扫描检查暂存对象及全部可达历史，规则命中只输出路径与规则名，不打印匹配秘密；覆盖GitHub Token、私钥标记、凭据URL、vault密钥材料及敏感文件名。它是模式扫描，不保证检出任意格式秘密；首次历史从本次生成的无运行数据源码开始，后续每次发布仍需检查。若秘密曾经发布，删除文件不够，先吊销/轮换，再按GitHub文档处理历史与缓存，不能声称改.gitignore就清除了泄露。

## 访问与日志

无域名部署默认仅127.0.0.1，HTTPS网关需明确配置域名与80/443。管理接口为独立密码+MFA会话/RBAC，产品隔离在后端执行。原项目请求日志不含请求体、Bearer、完整码或私钥；运维logs额外只允许已知JSON字段，丢弃不认识的外部输出。保留原始Docker日志应限制系统权限；应用或依赖本身若被恶意修改，不能靠一个过滤器保证无泄露。

构建从本地源码和哈希锁安装依赖，基础镜像解析并记录digest；镜像不包含运营vault或Git凭据。正常API低权限；维护容器在读取root文件后立即降权再操作业务数据，不提供任意远程命令功能。不能将未核验第三方分支或任意备份header指定的仓库代码当作可信安装来源。

## 备份和轮换

备份状态与key采用独立口令的认证加密；操作员权限能读取两份口令时仍可恢复全部业务，组织层面应使用独立保险库和最小权限。当前不集成云KMS或HSM，静态vault依赖主机权限/磁盘加密；请按自己的威胁模型评估。轮换、公钥兼容及泄露处置详见 `OPERATIONS.md`，离线客户端未更新前不能即时获知撤销或密钥泄露。
